# 围绕验证目标的协议分析

[英文版](SKILL.md)。本文供人工审核，描述的是同一个 skill，不是另一个需要注册的 skill。

这是面向调用者的集成 skill，不是分析执行 agent 的运行时方法。请求示例、产物、状态含义、前置依赖和术语见 [GUIDE.zh-CN.md](GUIDE.zh-CN.md)。复制时应保留整个目录；它不会自动安装到主 agent 中。

## 调用

保留原始验证目标、目标源码定位、直接调用者、观察边界、假设，以及选定的源码路径或给定调用图。将已有证明发现作为上下文提供，以区分重复观察和新推导。缺少输入或依赖时应明确报告，而不是悄悄扩大分析范围。

使用 `analyze-protocol prepare` 捕获新的输入包，使用 `run` 在显式超时限制内执行调查，使用 `status` 查看保留的证据及其是否仍匹配当前输入。这些命令由宿主的 `argus-spec` 包提供。执行预算及异步调度由调用者负责；调用这些命令不意味着执行 FM 分析、TLA 生成、测试或证明。

## 证据交接

保留运行目录、执行结果、是否仍匹配当前输入、源码与方法标识、覆盖范围，以及尚未解决的边界。交接某项发现时，保留其前提、源码引用、使用该事实的调用者、依赖、建议的区分性检查和剩余证明工作。候选全局性质可以说明建立和保持它的操作、排除的状态转移及适用的生命周期阶段；未覆盖的操作仍是未知项。

`completed` 表示建议性报告在结构上完整，不表示其语义已获验证。应明确保留部分完成、失败、超时和过期的结果。源码引用或分析者给出的标签不是执行证据；后续测试和验证器结果需要单独记录。

是否调用工具、采纳或拒绝候选、修改范围或实现、选择下一项证明义务，都由调用 agent 决定。本 skill 和报告均不选定最终规格，不关闭 proof-map 中的证明义务，不偿还信任／变更债务，也不认证缺陷。
